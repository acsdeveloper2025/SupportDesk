# Authentication API

Related: [../07-security-compliance.md](../07-security-compliance.md), [../08-rbac.md](../08-rbac.md), [../errors.md](../errors.md), [../audit-events.md](../audit-events.md).

## Policy

Authentication supports local credentials initially plus future OIDC/SAML/SCIM after OQ-03 resolution. Password, MFA, recovery, and session policies must be finalized before implementation.

## Security notes

Authentication errors must not disclose account, tenant, or membership existence. Privileged actions require step-up authentication or phishing-resistant MFA once policy is finalized.

M2.05 stores tenant-scoped server sessions before JWT and refresh-token rotation are implemented in M2.06. Until token transport lands, local API tests and development clients may pass the current session with `x-session-id`; production clients must move to the documented token/cookie mode when M2.06 is complete.
