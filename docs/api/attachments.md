# Attachments API

Related: [../07-security-compliance.md](../07-security-compliance.md), [../database/TABLES.md](../database/TABLES.md), [tickets.md](tickets.md).

| Method / URI                                       | Authentication                                  | Authorization                                | Request                                                   | Response                                   | Validation                                                | Errors                                      | Page/filter/sort | Rate limit            | Example                   |
| -------------------------------------------------- | ----------------------------------------------- | -------------------------------------------- | --------------------------------------------------------- | ------------------------------------------ | --------------------------------------------------------- | ------------------------------------------- | ---------------- | --------------------- | ------------------------- |
| `POST /api/v1/attachments/upload-sessions`         | Active tenant session                           | `attachment.create` scoped to ticket/comment | File metadata, ticket/comment target, size, hash optional | Upload session and constraints             | Size/type quota; target visibility; tenant storage policy | `VALIDATION_FAILED`, `QUOTA_EXCEEDED`       | None             | Upload throttle       | Request upload URL.       |
| `POST /api/v1/attachments`                         | Active tenant session or trusted inbound worker | `attachment.create`                          | Upload session ID, metadata, idempotency key              | Attachment in quarantine/scanning state    | Session valid; hash/size/type match                       | `VALIDATION_FAILED`, `CONFLICT`             | None             | Mutation              | Complete upload metadata. |
| `GET /api/v1/attachments/{attachment_id}`          | Active tenant session                           | `attachment.read` through ticket/comment     | None                                                      | Attachment metadata                        | Same tenant; visibility inherited                         | `NOT_FOUND`                                 | None             | Normal read           | Show file in ticket.      |
| `GET /api/v1/attachments/{attachment_id}/download` | Active tenant session                           | `attachment.download` through ticket/comment | None                                                      | Short-lived signed download or file stream | Scan state clean; purpose-bound access                    | `ATTACHMENT_NOT_CLEAN`, `AUTH_FORBIDDEN`    | None             | Download throttle     | Download clean file.      |
| `DELETE /api/v1/attachments/{attachment_id}`       | Active tenant session                           | `attachment.delete`                          | Version, reason                                           | Attachment redacted/soft-deleted           | Retention/legal hold; comment visibility rules            | `CONFLICT`, `AUTH_FORBIDDEN`                | None             | Sensitive mutation    | Remove accidental upload. |
| `POST /api/v1/admin/attachments/scan-callbacks`    | Trusted scan provider or worker auth            | Platform internal                            | Provider event, signature                                 | Accepted scan result                       | Signature, replay, tenant mapping from stored upload      | `AUTH_INVALID_SIGNATURE`, `REPLAY_DETECTED` | None             | Strict provider limit | Malware scan result.      |

Attachment content is untrusted until scan state is `clean`. Preview generation follows the same authorization and scan policy as download.
