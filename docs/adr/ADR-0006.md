# ADR-0006: Ticket Module v1 offset pagination

Status: Accepted for Ticket Module v1

## Context

Architecture foundation documents and [../13-rest-conventions.md](../13-rest-conventions.md) specify cursor pagination (`page[size]`, `page[after]`). The implemented Ticket and Comment list APIs use offset pagination (`page`, `pageSize`) with Zod-validated bounds.

Changing pagination mid-module would break the Ticket detail UI BFF and existing tests without improving product capability.

## Decision

Retain **offset pagination** for Ticket Module v1 list/count endpoints:

- `page` — 1-based page index (default 1)
- `pageSize` — page size (default 20, max 100)
- Response `meta` includes total records, total pages, and `hasNextPage`

Cursor pagination remains the **target** contract for search and high-volume queues (Epic 14+). A future ADR may supersede this for ticket lists once cursor infrastructure exists.

## Alternatives considered

- Migrate to cursor immediately: correct long-term, but is a feature/API redesign outside this hardening sprint.
- Dual support: unnecessary complexity for current scale.

## Consequences

- `docs/api/tickets.md` and `docs/api/comments.md` document offset as as-built.
- Clients must not assume cursor tokens on these endpoints.
- Performance/index planning for deep offsets remains a known Medium debt item.
