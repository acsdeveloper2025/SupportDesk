# ADR-0011: Workflow validation & governance (E11-I02)

Status: Accepted

## Context

E11-I01 shipped draft/publish with structural catalog validation only ([ADR-0010](ADR-0010.md)). Publish could accept definitions that reference missing users, illegal transitions, or self-triggering status loops. E11-I02 adds a validation/governance layer without executing workflows.

## Decision

1. **Validation report** `schemaVersion: 1` with `errors` and `warnings`. Issues sorted by `path`, then `severity`, then `code`. Only errors set `valid=false` and block publish.
2. **Draft writes** run structural + limit + group/UUID guards. **Publish and validate API** run full semantic, reference, limit, and same-definition cycle-risk checks.
3. **Group refs** (assign `groupId`, condition field `group`) fail with `WORKFLOW_GROUP_UNSUPPORTED` until Organizations/Groups exist (ADR-0008).
4. **User refs** must identify an ACTIVE user with a non-revoked role in the tenant.
5. **Limits:** max 10 triggers, 25 conditions, 25 actions, 64 KiB JSON, nesting depth 1 (flat AND only).
6. **Governance APIs:** `POST .../validate`, `POST .../clone-draft`, `GET .../versions/{from}/diff/{to}` using immutable version JSON snapshots; diff includes `generatedAt` and `changeCount`.
7. **No execution / outbox** in this slice (E11-I03).

## Consequences

- Clients can dry-run validation before publish.
- Published versions remain immutable; clone-draft fails if a draft already exists.
- Cross-workflow recursion remains deferred (requires runtime graph).
