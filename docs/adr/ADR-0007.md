# ADR-0007: Defer transactional outbox until automation consumers exist

Status: Accepted for pre-Workflow hardening; deferral lifted for implementation by [ADR-0009](ADR-0009.md); does not supersede decision-log ADR-004

## Context

Decision-log [ADR-004](../decision-log.md) requires committing domain state, audit events, and outbox records atomically. Ticket Module v1 writes domain rows and `audit_events` but has **no** `outbox_events` table or publisher.

Implementing a partial outbox without notification/workflow/email consumers would add schema and operational surface without delivering reliability benefits. This hardening sprint explicitly forbids introducing the outbox as a half-finished feature.

## Decision

1. **Do not implement** the transactional outbox in this hardening sprint.
2. Keep decision-log ADR-004 as the binding target architecture.
3. Require outbox (or an accepted superseding ADR) before **Workflow execution (E11-I03)** and before durable notification dispatch.
4. Ticket Module v1 may continue emitting in-process audit events only; document that domain events are not yet durable for async consumers.

## Alternatives considered

- Implement outbox now with a no-op consumer: schema-only change that creates migration/ops burden and false confidence.
- Drop ADR-004: unacceptable — automation and notifications need at-least-once intent.

## Consequences

- E11-I01 (definition CRUD) may proceed after hardening gate without outbox.
- E11-I03 / notification workers remained blocked on outbox delivery until ADR-0009.
- ADR-0009 implements the outbox as part of E11-I03 and is the binding implementation record going forward.
- Technical debt item TD-H6 tracks implementation guidance (see hardening report).

## Implementation guidance (when unblocked)

1. Add `outbox_events` per [../database/TABLES.md](../database/TABLES.md).
2. Write outbox rows in the same Prisma transaction as ticket/comment mutations that must fan out.
3. Add a claimed worker with lease, backoff, and idempotent handlers.
4. Cover with replay and dual-write failure tests (T-AUDIT / T-NOTIFY).
