# ADR-0002: Authentication strategy

Status: Accepted assumption pending OQ-03 validation

## Context

SupportDesk must support enterprise identity while remaining implementable in early milestones. [07-security-compliance.md](../07-security-compliance.md) requires standards-based identity, privileged MFA, session revocation, and audited elevation. Exact identity providers, SSO protocols, MFA behavior, and SCIM support remain open in OQ-03.

## Decision

Use a standards-based authentication boundary with local credentials only if required for bootstrap, and design for OIDC/SAML SSO, SCIM provisioning, MFA, session revocation, refresh-token rotation, and step-up authentication.

Authorization remains separate from authentication and is evaluated through Tenant Membership and scoped Permissions from [../permissions-matrix.md](../permissions-matrix.md).

## Alternatives considered

- Local-only authentication: fastest but weak for enterprise adoption.
- SSO-only authentication: enterprise-ready but can block bootstrap, demos, and tenants without IdP readiness.
- Hybrid bootstrap plus standards-based SSO: flexible and compatible with future enterprise requirements.

## Consequences

- Sessions must store tenant selection, device metadata, revocation state, expiry, and token family rotation.
- Privileged actions require MFA/step-up once policy is finalized.
- Authentication errors must avoid account and tenant enumeration.
- Identity provider integrations must be isolated adapters, not core domain dependencies.
