# E11-I03 — Workflow Execution Engine & Transactional Outbox Implementation Plan

**Goal:** Implement deterministic, tenant-scoped Workflow execution from durable domain events using a transactional outbox, background worker pipeline, ordered action execution, transient failure retries, dead-lettering, recursion depth budget, execution history, and minimal notification intents.

---

## User Review Required

> [!IMPORTANT]
> **Key Architectural Guarantees & Constraints:**
>
> 1. **Transactional Outbox Packaging (ADR-0012 / ADR-004):** Domain mutations (ticket creation/status/assignment, comments, SLA events) append `outbox_events` atomically in the same database transaction. The API request path remains fully async and does not perform workflow execution inline.
> 2. **Single Transaction Per Action:** Each workflow action executes in its own isolated DB transaction. Mid-workflow failures resume from the first non-`SUCCEEDED` attempt (`workflow_action_attempts`).
> 3. **Recursion Control (`automationDepth`):** Platform hard cap is 3. Events generated by workflow actions carry `automationDepth = parent + 1`. Depth-capped events record skip audit (`workflow.automation_depth_capped`) without rolling back the producing domain mutation.
> 4. **Deferred Elements:** Provider notification delivery (email/SMS), webhooks, custom scripts, schedules, and parallel actions remain deferred per spec non-goals.

---

## Open Questions

- None blocking. Standard defaults applied per spec:
  - Auto-pause failure threshold: $K = 10$ dead-lettered executions in window $W = 1\text{ hour}$.
  - Worker poll interval: $500\text{ ms}$, batch size: $20$ rows.

#### [NEW] [workflow-runtime.module.ts](file:///Users/mayurkulkarni/Downloads/SupportDesk/apps/api/src/workflows/runtime/workflow-runtime.module.ts)

- `WorkflowDispatcherService`:
  - Receives outbox batch from claimer.
  - Checks depth budget. If capped: emits audit `workflow.automation_depth_capped`, marks outbox `PROCESSED`, returns.
  - Fetches enabled & published workflows for `(tenantId, eventType)`, ordered by container `priority` ascending.
  - Inserts deduplicated `workflow_executions` row.
  - Evaluates snapshot conditions. If false, marks execution `SKIPPED_CONDITIONS`.
  - Dispatches actions sequentially by `ordinal`.
- `WorkflowExecutorService`:
  - Runs each action in its own database transaction (`tx`).
  - Checks `workflow_action_attempts` to skip already `SUCCEEDED` ordinals (resumability).
  - Invokes domain service via `AutomationActor` (system principal with tenant context).
  - Emits child outbox events with `depth = parentDepth + 1` if domain state was modified.
  - Manages action attempt retries (max 5) with exponential backoff & dead-lettering.
  - Evaluates failure threshold: if $\ge K$ dead-lettered executions within window $W$, auto-pauses workflow (`enabled=false`, `pausedReason="auto_paused_failure_threshold"`) and logs audit `workflow.paused`.
